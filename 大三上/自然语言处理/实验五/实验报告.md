## 一、实验目的
- 构建面向中文文本的检索增强生成（RAG）系统。
- 掌握文档加载、切分、向量化、相似度检索、提示模板与重排序等流程。
- 对比“检索+生成（RAG）”与“直接生成”的差异，并给出简单评估。

## 二、实验环境与依赖
- 操作系统：Windows 10/11（PowerShell）
- 主要依赖：
  - langchain、langchain-community、langchain-core、langchain-text-splitters
  - langchain-huggingface（可选，优先使用其 HuggingFaceEmbeddings）
  - sentence-transformers、transformers、torch、faiss-cpu、pandas、numpy、rouge-score
- 模型与索引缓存：
  - Hugging Face 默认缓存：`%USERPROFILE%\.cache\huggingface\hub`
  - 项目向量索引：`faiss_index/`

## 四、方法与流程（参考《实验指导.md》并结合本程序）
1. 文档加载与分块
   - 使用 `DirectoryLoader` 加载 `.txt` 文档；
   - 采用 `RecursiveCharacterTextSplitter` 进行中文友好分块（设置 `chunk_size=500, chunk_overlap=50`）。
2. 向量化与索引
   - 默认使用中文嵌入模型（如 `moka-ai/m3e-base` 或 `BAAI/bge-small-zh-v1.5`）；
   - 通过 FAISS 构建与保存本地向量索引；再次运行可直接加载索引。
3. 相似度检索
   - 使用 `similarity_search_with_score` 返回 TopK 文档与相似度分数。
4. 生成模型加载与回答生成
   - 默认小模型：`Qwen/Qwen2.5-1.5B-Instruct`；
   - RAG 模式将检索上下文拼接到提示中；普通模式不含上下文。
5. 提示增强与结构化回答
   - 增强模板要求“仅依据参考文档作答、分点陈述、无法回答需明确说明”等。
6. 混合检索与重排序（可选）
   - 混合：语义检索 + 简化 BM25（缺少 `rank_bm25` 时自动回退为纯语义）；
   - 重排序：`BAAI/bge-reranker-base`（网络不畅时可 `--disable-rerank` 跳过）。
7. 简单评估
   - 指标：长度、信息点数量（基于标点计数）、实体提及次数；
   - 可选 ROUGE（`rouge-score`）。

## 五、关键实现说明
- 兼容新版 LangChain：
  - `RecursiveCharacterTextSplitter` 来自 `langchain_text_splitters`；
  - `Document` 来自 `langchain_core.documents`；
  - `HuggingFaceEmbeddings` 优先 `langchain_huggingface`，否则回退 `langchain_community`。
- FAISS 索引加载：启用 `allow_dangerous_deserialization=True` 以兼容新版序列化。
- 异常与降级：
  - BM25 不可用或失败则自动退化为纯语义检索；
  - 网络不畅可通过镜像与预下载。

## 六、运行命令与参数
- 快速验证（跳过 LLM）：
```powershell
python rag_lab.py --skip-llm --embedding-model "BAAI/bge-small-zh-v1.5" --query "中国的人工智能发展现状如何？"
```
- 完整运行（含生成与评估）：
```powershell
python rag_lab.py --model-name "Qwen/Qwen2.5-1.5B-Instruct" --embedding-model "BAAI/bge-small-zh-v1.5" --query "中国的人工智能发展现状如何？"
```
- 跳过重排序避免下载超时：
```powershell
python rag_lab.py --disable-rerank --model-name "Qwen/Qwen2.5-1.5B-Instruct" --embedding-model "BAAI/bge-small-zh-v1.5" --query "中国的人工智能发展现状如何？"
```
- 常用环境变量（Windows PowerShell）：
```powershell
$env:HF_ENDPOINT="https://hf-mirror.com"   # 国内镜像
$env:HF_HOME="D:\hf_cache"                # HuggingFace 缓存目录
$env:TRANSFORMERS_CACHE="D:\hf_cache\transformers"
$env:SENTENCE_TRANSFORMERS_HOME="D:\hf_cache\st"
$env:TORCH_HOME="D:\torch_cache"
```

## 七、实验结果与分析
- 检索阶段：成功返回与问题相关的中文片段（含相似度）。
- 生成阶段（RAG vs 普通）：
  - RAG 回答更贴合文档事实，结构化更好；
  - 普通生成可能出现泛化描述或事实不充分。
- 简单评估（示例）：
  - 长度、信息点、实体提及等指标对比展示 RAG 的信息覆盖更稳定；
  - 在文档较少场景，RAG 优势受限，需扩充知识库。

## 八、问题与解决
- Hugging Face 下载超时：设置 `HF_ENDPOINT` 镜像或预下载。
- 版本冲突：按提示升级 `transformers` 与 `huggingface-hub` 版本范围。
- `rank_bm25` 缺失：
  - 安装：`pip install rank_bm25`；
  - 或使用 `--disable-rerank` 跳过重排序。

## 九、优化与改进方向
- 知识库扩充与清洗；中文分句更细致的切分策略；
- 使用更强中文嵌入与重排模型（本地或服务化）；
- 缓存与离线资源管理（统一缓存目录、打包模型）；
- 提示模板的结构化输出（JSON/Markdown）与事实引用标注。

## 十、结论
- 完成中文 RAG 管线的工程化落地：加载→分块→向量→检索→生成→评估；
- 在网络与硬件受限条件下，通过镜像、降级与参数开关保证可复现；
- RAG 能在小数据场景显著提升回答的可控性与可溯源性。
